# 🚀 基于核心真题 (Q10-Q24) 的预测追问集

## 1. 关于 BCJR 与 Viterbi 的深度辨析 (对应 Q10, Q14, Q19, Q24)

### 预测问题 A：既然 Viterbi 和 BCJR 在高信噪比下性能曲线重合，为什么 Turbo 码必须用 BCJR (或 SISO 算法) 而不能用普通的 Viterbi？
- **关键词**：**迭代需要**、**置信度传递**、**软信息更新**
- **完整答案**：因为 Turbo 码的核心机制是迭代译码。迭代需要两个译码器之间互相传递“我对这个比特是 0 还是 1 有多大把握”（即软信息/LLR）。普通的 Viterbi 算法（即使是软输入）通常输出的是硬判决路径（0 或 1），或者是某条路径的度量值，它难以生成每个比特独立的后验概率。只有 BCJR 这种 SISO（软输入软输出）算法，才能计算出包含“外在信息”的 LLR，从而在迭代中不断修正另一个译码器的判断。

### 预测问题 B：Viterbi 算法在回溯时，如果出现两条路径度量值完全一样（概率相同），代码该怎么选？会对性能有影响吗？
- **关键词**：**随机选择**、**影响微小**、**高 SNR 无视**
- **完整答案**：在工程实现中，如果遇到度量值相同，通常随机选择一条，或者固定选择其中一条（如选索引小的）。影响：这种“歧义”通常发生在噪声很大导致路径难以区分时。但在高信噪比下，正确路径的度量通常明显优于错误路径，几乎不会出现完全相等的情况。因此，这种随机选择对最终误码率的影响微乎其微。

## 2. 关于 自由距离与性能 (对应 Q11, Q12, Q17)

### 预测问题 C：你说 $d_{free}$ 决定了性能，那是不是 $d_{free}$ 越大的码，在任何信噪比下性能都更好？
- **关键词**：**渐进性能**、**低信噪比交叉**、**路径重数**
- **完整答案**：不一定。$d_{free}$ 主要决定了高信噪比（High SNR）区域的性能（误码率曲线的斜率/渐进特性）。但在低信噪比区域，误码率还受到具有 $d_{free}$ 距离的路径数量（称为路径重数或 Multiplicity）以及次小距离路径的影响。有时候 $d_{free}$ 大的码，其邻居路径非常多，导致在低信噪比下性能反而不如 $d_{free}$ 稍小但结构简单的码。

### 预测问题 D：增加约束长度 $K$ 可以增加 $d_{free}$，为什么我们不把 $K$ 设得特别大（比如 100）？
- **关键词**：**指数复杂度**、**物理实现瓶颈**、**Viterbi 崩溃**
- **完整答案**：因为译码复杂度是 $K$ 的指数函数。状态数 = $2^{K-1}$。如果 $K=7$，状态是 64；如果 $K=100$，状态数是 $2^{99}$，这是一个天文数字。Viterbi 算法需要存储和更新每一个状态的度量值，$K$ 过大会导致计算量 and 存储需求超出任何物理硬件的承受能力。

## 3. 关于 归零与系统结构 (对应 Q13, Q18, Q20)

### 预测问题 E：在 Q20 中提到系统码归零需要“反馈计算”，如果我不做这个反馈计算，直接强行补 0 会发生什么？
- **关键词**：**状态不归零**、**末尾误码**、**格图发散**
- **完整答案**：对于递归系统码（RSC），如果直接补 0，寄存器里的状态不会回到全零状态（因为有反馈回路存在，0 输入可能会产生非 0 反馈）。后果：译码器通常假设结束时状态为 0。如果实际编码未归零，译码器在回溯时会强制从状态 0 开始找路径，这会与实际发送的路径不匹配，导致数据包末尾出现大量误码（Edge Effect），严重影响帧错误率。

## 4. 关于 算法复杂度与实现 (对应 Q15, Q16, Q19)

### 预测问题 F：BCJR 的 Log-MAP 算法中，为什么 $\max^*(x, y)$ 运算通常用查表法实现？
- **关键词**：**修正项**、**非线性函数**、**速度优化**
- **完整答案**：$\max^*(x, y) = \max(x, y) + \ln(1+e^{-|x-y|})$。后面这一项 $\ln(1+e^{-|x-y|})$ 是非线性的修正项，涉及指数和对数运算，在 FPGA 或 DSP 中直接计算非常耗时。由于这个修正项的值只与 $|x-y|$ 的差值有关，且当差值很大时修正项趋近于 0，因此工程上通常将其做成一个小的查找表 (LUT) 来替代实时计算，以平衡精度和速度。

## 5. 概念陷阱题 (对应 Q22, Q23)

### 预测问题 G：分组码（Block Code）能用 Viterbi 算法译码吗？
- **关键词**：**可以**、**网格表示**、**复杂度限制**
- **完整答案**：理论上是可以的。只要分组码（如汉明码）可以表示为网格图 (Trellis) 的形式（例如 Wolf Trellis），就可以应用 Viterbi 算法寻找最短路径。但是，对于长分组码，其网格图的状态数通常极其巨大，导致 Viterbi 算法并不实用，所以分组码通常用代数译码或置信传播算法。
